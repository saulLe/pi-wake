# 工作台代码规范（Velocity / SQL）

本文件在工作目录启动时自动加载。适用范围：Velocity 模板、SQL 查询、数据开发脚本。

## 沟通风格

- 结论先行，回答简洁，不用 emoji，不写客套话。
- 改动代码前先说清"为什么改"，改完说清"改了什么"。
- 用户问问题时，先回答，再动手改。

## Velocity 模板规范

- **禁止使用 `#set` 语句**。所有变量赋值改用内联条件表达式。
  - 反例：`#set($a = $x) ## ... $a`
  - 正例：直接在表达式里用 `$!{...}`、三元风格的条件输出或工具方法内联判断。
- 模板里不做复杂逻辑计算，判断逻辑尽量下沉到 SQL 或数据层。
- 输出前确认空值安全：使用 `$!{}` 形式避免输出字面 `$var`。

## SQL 规范

- **优先用内联条件表达式**替代冗余的 CASE/临时变量堆叠（与 Velocity 侧保持一致）。
- 表关联逻辑：
  - `dim_tracking_employee` 与 `dim_member_counselor` 关联时用 **LEFT JOIN**，保留左表全部记录。
  - 需要合并两处来源时，用 **UNION / UNION ALL** 明确去重语义；列顺序、列别名必须对齐。
  - 关联键、过滤条件写清楚，避免隐式笛卡尔积。
- 简化优先：能用一个查询表达的不要拆成多个；去掉不被使用的字段、JOIN 和子查询。
- 识别并删除死代码：无引用的字段、恒真/恒假条件、重复过滤。
- 修改 SQL 后说明：改变了哪些 JOIN / UNION 语义，是否影响行数。

## 工作方式

- 渐进式优化：先给出最小改动，再根据反馈迭代，不要一次性大改。
- 每次改动后运行项目约定的检查命令（见各子项目 README）。
- 遇到不确定的业务规则，直接问，不要猜。
