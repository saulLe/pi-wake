# Velocity / SQL 代码约定（详细参考）

供 `velocity-sql` skill 按需读取。

## Velocity 模板

### 禁止 `#set`，改用内联表达式

`#set` 让模板产生隐式状态，难以追踪和优化。优先方式：

- 需要默认值：用 `$!{var}`（变量为空时不输出字面量）。
- 需要条件输出：把判断放在数据准备阶段，模板只负责渲染。
- 需要在多处复用同一个值：在数据层算好，作为对象字段传入。

### 空值安全

- 一律用 `$!{...}` 形式引用变量，避免 null 时输出 `$var` 字面量。
- 字符串拼接、条件判断前确认变量是否已定义。

### 逻辑下沉

- 模板里不写复杂条件树、循环内计算。
- 复杂判断交给 SQL（CASE WHEN）或 Java/脚本层。

## SQL

### 表关联

- `dim_tracking_employee` LEFT JOIN `dim_member_counselor`：保留员工维表全部记录， counselor 侧无匹配补 NULL。
- 合并两个来源的数据用 UNION（去重）或 UNION ALL（保留重复，性能更好），按业务需求选择并说明。
- UNION 各分支：列数量、列顺序、列别名必须一致。

### 简化

- 去掉未出现在 SELECT / WHERE / 后续 CTE 的 JOIN。
- 去掉恒真（`1=1`）或恒假条件、重复过滤。
- 能用一个 CTE 表达清楚的不嵌套多层子查询。
- 字段列表显式写出，避免 `SELECT *`（除非调试）。

### 死代码识别

- 无引用的临时表、CTE、字段。
- 被后续条件覆盖的冗余过滤。
- 永远不进入的分支。

## 沟通

- 每次改动列出：改动点、语义影响、是否影响结果行数。
- 渐进式迭代，一次只解决一类问题。
